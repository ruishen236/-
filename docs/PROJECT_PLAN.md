# StockLab 项目长期开发路线

## 项目目标与边界

StockLab 是面向零基础用户的中国 A 股股票学习与模拟交易网站。长期目标包括系统学习、100 万元虚拟资金模拟交易、历史行情与 K 线、技术指标以及 Python 策略回测。前后端分离，先支持 Windows 本地运行，再逐步准备公开部署。

仅使用虚拟资金，不连接真实证券账户、不提供真实交易入口。优先使用免费开源工具和可合法使用的数据，不依赖付费服务。学习内容与回测结果用于教学，不承诺投资收益。

## 实施方式

每阶段只实现明确要求的功能；完成相关测试并记录运行方法后，再推进下一阶段。不擅自重构正常运行的模块。下列路线是规划，不表示已有实现，也不授权一次性实现所有阶段。

| 阶段 | 当前范围 | 验收条件 |
| --- | --- | --- |
| 0：文档初始化 | 路线、架构、进度、开发规范 | 四份文档完整且互相一致；不引入应用代码 |
| 1：可运行骨架 | React + TypeScript + Vite、Tailwind CSS、FastAPI、SQLite + SQLAlchemy；首页与健康检查 | Windows 可分别启动前后端；首页可请求健康接口；后端基础测试通过；前端类型检查和构建通过 |
| 2：股票学习 MVP | 基础概念、风险、交易流程的分章节内容与阅读页面 | 用户可以浏览完整入门路径；规则性内容附权威参考和适用日期；导航及内容接口验证通过 |
| 3：历史行情 | 明确来源的数据导入、股票查询、日线 K 线、成交量；先实现一个明确公式的技术指标 | 数据标注来源、覆盖日期、是否模拟及更新时间；导入校验和指标测试通过；图表展示与输入数据一致 |
| 4：模拟交易 MVP | 单个本地模拟账户，初始虚拟资金 1,000,000 元；下单、成交记录、持仓、资金与收益展示 | 已确认的交易规则得到测试覆盖；订单、资金和持仓以事务一致更新；重复请求不重复成交；界面明确虚拟交易 |
| 5：Python 回测 MVP | 一个简单可解释策略、参数、回测区间、交易记录、净值及基本绩效指标 | Pandas + NumPy 实现并通过 Pytest；明确复权、费用、成交时点和滑点假设；避免未来数据泄漏；结果可复现 |
| 6：完善与部署准备 | 根据实际需求增加内容、策略和指标；部署文档、备份、访问控制及安全检查 | Windows 本地流程继续通过；公开部署前验证隔离、数据许可、备份恢复及资源限制 |

阶段 1 已按本次用户要求完成界面和演示接口，详见 PROGRESS.md。原路线中的 SQLite 接入延后到需要账户持久化的阶段；本次不实现真实行情、复杂交易或回测。其余阶段仍是规划，不是已完成内容。

## 开发前必须明确的决策

- 行情来源尚未选定。优先评估合法免费来源、授权范围、稳定性及限流；必要时先用可导入的本地 CSV 或明确标识的模拟数据。不能将模拟数据标为真实行情。
- 模拟交易首版的证券范围、交易日历、成交时点及价格模型尚未确定。建议从范围明确的普通 A 股历史日线开始，不能声称提供实时行情。
- A 股 T+1、申报数量、涨跌幅限制、停牌、特殊股票、不同板块、费用和历史规则变化需要依据交易所等权威材料逐项核实。不能用统一参数覆盖所有证券和日期。
- 回测必须明确复权方式及公司行动处理、基准、费用、滑点和可交易性。未支持的情形要限制输入并说明，不能悄悄忽略。
- 公开部署前再决定多用户认证、账户隔离、任务调度和数据库升级。SQLite 适用于首版本地流程；是否迁移依据实际并发与运行需求决定。

## 每阶段交付要求

交付范围内的代码、必要的中文说明、相关测试结果、创建或修改文件清单、Windows PowerShell 运行步骤，以及已知限制。同步更新 `docs/PROGRESS.md`；架构确有变化时更新 `docs/ARCHITECTURE.md`。
